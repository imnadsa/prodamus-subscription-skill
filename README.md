# prodamus-subscription-skill

**Скилл для Claude (и любого другого ИИ-агента), который подключает подписочную оплату к вашему сервису за один вечер.**

Вы отдаёте агенту этот скилл — он заводит таблицы, поднимает вебхук приёма платежей,
закрывает доступ неоплатившим и объясняет вам, что проверить перед запуском.
Отдельно объяснять агенту ничего не нужно: вся схема, все шаги и все грабли уже внутри.

Скилл написан по боевой подписочной системе: рекуррентные списания, несколько
платёжных кабинетов, двухуровневый биллинг (организация + её единицы),
саморегистрация с лендинга.
Всё, за что мы заплатили деньгами и потерянными платежами, лежит в
[`references/pitfalls.md`](skills/prodamus-subscription/references/pitfalls.md) —
это самая полезная часть репозитория.

Платёжка в примерах — **Продамус**, потому что в РФ она закрывает рекуррент без
своего PCI DSS. Но 90% скилла (модель данных, идемпотентность, машина статусов,
гейт доступа) не зависит от шлюза: под ЮKassa, CloudPayments или Stripe меняется
только проверка подписи и имена полей.

## Установка (2 минуты)

**Claude Code — на все проекты сразу:**

```bash
git clone https://github.com/imnadsa/prodamus-subscription-skill.git
cp -r prodamus-subscription-skill/skills/prodamus-subscription ~/.claude/skills/
```

**Только в один проект** (тогда скилл поедет в репозиторий вместе с кодом):

```bash
mkdir -p .claude/skills
cp -r prodamus-subscription-skill/skills/prodamus-subscription .claude/skills/
```

Проверить, что подхватился: в Claude Code наберите `/prodamus-subscription`.
Или просто скажите словами: **«подключи подписку по этому скиллу»** — агент найдёт
его сам по описанию.

**Другой агент (Cursor, Codex, свой на API):** дайте ему файл
[`SKILL.md`](skills/prodamus-subscription/SKILL.md) как системную инструкцию —
он самодостаточен, формат Markdown понимают все.

## Что получится на выходе

```
        Клиент жмёт «Оплатить»
                 │
                 ▼
   ┌──────────────────────────┐
   │  Форма оплаты (Продамус) │   в ссылке order_num = slug клиента
   │  рекуррент N ₽ в месяц   │   ← это единственная ниточка «платёж → клиент»
   └────────────┬─────────────┘
                │ вебхук с подписью HMAC-SHA256
                ▼
   ┌──────────────────────────┐
   │  /webhooks/payment       │  1. проверил подпись
   │  (edge function)         │  2. понял, ЗА ЧТО платёж (plan_id)
   │                          │  3. нашёл клиента (4 способа)
   │                          │  4. записал событие с event_key ← замок от дублей
   │                          │  5. продлил срок: max(старый, сегодня+31)
   └────────────┬─────────────┘
                │
                ▼
   ┌──────────────────────────┐        ┌────────────────────────────┐
   │  clients                 │        │  payment_events            │
   │  subscription_status     │        │  вся история + raw_payload │
   │  subscription_expires_at │        │  event_key UNIQUE          │
   └────────────┬─────────────┘        └────────────────────────────┘
                │
                ▼
   ┌──────────────────────────┐
   │  Гейт в приложении       │  hasAccess = f(status, expires_at)
   │  нет доступа → пейволл   │  чистая функция, покрыта тестами
   └──────────────────────────┘
```

Четыре сущности, больше ничего не нужно:

| Что | Зачем |
|-----|-------|
| `clients.subscription_status` + `expires_at` | текущее состояние подписки — по нему пускают в кабинет |
| `payment_events` | журнал всех событий шлюза, включая сырой payload, и **замок от дублей** |
| вебхук | единственное место, где меняется статус подписки |
| гейт | чистая функция «пускать или нет», один вызов в корне приложения |

## Три правила, ради которых всё это писалось

1. **Ни один платёж не должен потеряться молча.** Сбой базы — отвечайте 500, шлюз
   повторит. Ответили 200 — платёж исчез навсегда, а клиент считает себя оплатившим.
2. **Оплаченный период неприкосновенен.** Отмена автопродления, провал следующего
   списания, деактивация — не отбирают то, за что уже заплачено.
3. **Повтор доставки не должен ничего продлевать.** Идемпотентность — на UNIQUE-индексе
   в базе, а не на проверке «а не было ли такого события минуту назад».

Подробнее и с историями — в [pitfalls.md](skills/prodamus-subscription/references/pitfalls.md).
