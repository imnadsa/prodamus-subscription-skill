# Гейт доступа и пейволл

## Чистая функция, а не «условие в компоненте»

Решение «пускать или нет» должно быть одной функцией без побочных эффектов —
её можно покрыть тестами и прочитать глазами:

```ts
export function hasAccess(
  status: SubscriptionStatus,
  expiresAt: string | null,
  now: Date = new Date(),
): boolean {
  if (status === 'free') return true;                    // выдан вручную
  if (status === 'active' || status === 'past_due') {
    if (!expiresAt) return status === 'active';          // ручная активация без даты
    return now < new Date(expiresAt);
  }
  return false;                                          // trial без даты, expired
}
```

Полная версия с хуком — [`../assets/access.ts`](../assets/access.ts).

## Где вызывать

Один раз, в корне приложения, до отрисовки контента:

```tsx
if (loading)             return <Loader />;          // ещё грузимся — НЕ блокируем
if (!hasAccess)          return <PaywallScreen />;   // подписка организации
if (!branchAccess)       return <BranchPaywallScreen />;  // конкретная единица
return <App />;
```

Порядок гейтов имеет значение: сначала организация (не оплачена — закрыт весь
кабинет), потом единица (закрыта только она, на оплаченные можно переключиться).

## Правила, которые дороже всего нарушать

**Пока данные грузятся — не блокировать.** Пейволл, мигнувший платящему клиенту
на секунду, читается как «сервис сломался и украл мои деньги». Показывайте лоадер.

**Нет данных о филиале/проекте — не блокировать.** Блокировка по отсутствию
информации всегда выглядит поломкой. Блокируйте только по явному «не оплачено».

**Главную единицу не блокировать никогда** — она покрыта подпиской организации,
которая уже проверена гейтом выше. Проверяйте это по признаку «главный», а не
только по статусу: статус может разойтись с реальностью из-за дефолта колонки.

**Экран оплаты — рабочий, а не заглушка.** На нём должно быть:

- сколько стоит и за какой период;
- кнопка, ведущая на ссылку оплаты **с уже подставленным** `order_num`;
- телефон/почта поддержки — часть людей платит по счёту, а не картой;
- если единиц несколько — список оплаченных с возможностью переключиться;
- если доступ кончился только что — дата окончания словами («доступ был до 12 августа»).

**Предупреждать заранее.** За 3–5 дней до `expires_at` — мягкая плашка в интерфейсе.
Стоит один вечер работы и снимает половину обращений «почему меня выкинуло».

## Что показывать по статусам

| Статус | Что видит пользователь |
|--------|------------------------|
| `active`, дней много | ничего |
| `active`, осталось ≤5 дней | плашка «подписка продлится N-го числа» |
| `past_due`, период ещё идёт | плашка «не удалось списать, проверьте карту» |
| `past_due`/`expired`, период кончился | экран оплаты |
| `free` | ничего (и никаких дат — их тут нет) |
